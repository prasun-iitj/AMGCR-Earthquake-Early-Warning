# CONTRIBUTING.md

# AMGCR Earthquake Research - Contribution Guidelines

## Purpose

This document defines the standards and workflow for contributing to the
AMGCR_Earthquake_Research repository.

---

# Contribution Principles

Every contribution should:

- Improve the project.
- Be reproducible.
- Be well documented.
- Follow the established project structure.
- Preserve research integrity.

---

# Development Workflow

1. Read the project documentation.
2. Understand the current milestone.
3. Create or update code in small, focused changes.
4. Test the implementation.
5. Update the relevant documentation.
6. Commit the changes with a meaningful message.

---

# Coding Standards

- Follow PEP 8.
- Use descriptive names.
- Keep functions short and modular.
- Add docstrings for public functions.
- Avoid duplicated code.
- Avoid hard-coded values.

---

# Git Commit Message Format

Examples:

- feat: add earthquake event downloader
- fix: resolve waveform parsing issue
- docs: update project roadmap
- refactor: simplify preprocessing module
- test: add waveform validation tests

---

# Pull Request Checklist

Before merging:

- [ ] Code runs successfully.
- [ ] Documentation updated.
- [ ] No unnecessary files added.
- [ ] Folder structure preserved.
- [ ] Changes tested locally.

---

# Documentation Policy

Whenever code changes:

- Update PROJECT_STATUS.md if a milestone changes.
- Update CHANGELOG.md for significant updates.
- Keep README.md accurate.

---

# Project Philosophy

Understand → Build → Verify → Document → Improve

Quality and reproducibility take priority over speed.
